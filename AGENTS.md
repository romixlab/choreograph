# Working on choreograph

Guidance for AI agents and contributors. Read this before changing code.

choreograph plans and runs jobs over shared resources: each job needs some resources (instruments, connections,
RAM, CPU, a node), goes through setup, run and cleanup, and carries a priority and time bounds. The same core
serves a hardware-in-the-loop test bench and a merge queue on a few build machines; only the kinds of resources
differ.

## FEATURES.md is the source of truth

[FEATURES.md](FEATURES.md) lists every feature with its status, every known bug and what is planned, with stable
IDs per area (`CORE-1`, `PLAN-2`, ...).

- Read the relevant area before starting.
- Name IDs with a short slug in prose: `PLAN-1 list-scheduler`, not a bare `PLAN-1`. Commit messages, the
  CHANGELOG and code `TODO`s keep the bare ID.
- Update it in the same commit as the code: mark items ✅/🚧/🐛 with a pointer to the code, add bugs you find but
  don't fix (next free ID of the area), move obsolete items to *Dropped and superseded*. Never renumber or reuse
  IDs.
- No status anywhere else (README checklists, TODO files). Code `TODO`s that matter reference an ID:
  `// TODO(PLAN-2): ...`.

## CHANGELOG.md records every change

- Every change a user of the crates or the CLI would notice gets an entry under `## [Unreleased]` in the same
  commit: `### Added`, `### Changed`, `### Fixed`, `### Removed`, short, with the feature ID in parentheses. Mark
  API breaks with **Breaking:**.
- Branches never touch the version (`[workspace.package] version`, `## [x.y.z]` headings, tags). A release moves
  `[Unreleased]` under a new `## [x.y.z] - YYYY-MM-DD` heading with the version bump in one commit and tags it
  `vX.Y.Z`. Before 1.0 a patch bump is additive or compatible, a minor bump breaking.

## Layout

Cargo workspace, edition 2024, one shared version.

- `choreograph/`: the library. No IO, no async runtime, no wall clock: time and outside happenings come in as
  timestamped events, decisions go out as data (sans-IO), so tests, the simulator and a real executor drive the
  same code.
  - `time.rs`: `Time` and `Dur`, integer milliseconds; parsing and printing of `1h30m`-style values.
  - `model.rs`: nodes, resource kinds, resources (capacity, labels, optional states with a safe state), jobs
    (needs, phases with p50/p90 estimates, deps, priority class, weight, release time, due date), groups;
    validation.
  - `state.rs`: the runtime bookkeeping the planner reads and drivers update: job status, who holds what,
    capacity checks (it refuses an over-capacity start).
  - `live.rs`: `Live`, a model and its state that change at runtime: jobs submitted and compacted (ids
    renumbered in order), capacities set from measurements, nodes added, up, down or lost, labels and policy
    labels changed.
  - `plan.rs`: the `Planner` trait, `Plan` (starts, reservations, wait reasons), `WaitReason`, and `Fifo`, the
    first-fit baseline planner.
  - `list.rs`: `ListScheduler`, the main planner: effective priority (class, aging, deadline urgency), placement
    scoring, EASY and conservative backfilling on a free-capacity profile, the forward plan (`forecast`).
  - `policy.rs`: `Policy`, the list scheduler's settings with defaults, loadable from TOML.
  - `estimates.rs`: the `Estimates` trait and `Learner`, which learns an EWMA mean and streaming p50/p90/p99
    per (job kind, phase, resource, node) from observed durations, blended with a prior per job kind and phase
    for a cold start.
  - `trace.rs`: the event trace shared by the simulator, the executor journal and the GUI.
  - `theory.rs`: queueing and scheduling formulas (M/M/c, Erlang C, Kingman, Pollaczek–Khinchine, Cobham, ...)
    to compare measurements with predictions.
  - `jobset.rs` (feature `toml`): the TOML job-set format and its loader.
- `choreograph_cli/`: the `choreograph` binary, a thin layer over the library.
- `examples/`: job sets in TOML. All example and test data is synthetic or generated by the tests.

## Rules for the code

- **No IO and no clock in the library.** Never `std::time::SystemTime`, `Instant`, threads, files or sockets in
  `choreograph/`; the caller passes `Time`. Randomness only from a seeded generator passed in.
- **Deterministic.** The same inputs give the same plan and the same trace, bit for bit: integer time, ordered
  collections (`BTreeMap`, `Vec`), ties broken by a stated rule ending in the id order.
- **Safe by construction.** A start acquires every need at once or nothing; `State` refuses anything over
  capacity; cleanup is reached from every state after a start.
- **Every tunable is a setting** with a default and a doc line, never a bare constant in the code.
- **Pure-Rust dependencies**, no `-sys` crates or C toolchains; check `cargo tree` for `cc`/`bindgen` when adding
  one, and pick features that avoid them.
- **Public wording** in everything in the repo: code, docs, commit messages, CHANGELOG. No internal names, no
  design or review notes (those live outside the repo); a docs page explains the feature as it is.

## Tests

- `just test` runs the whole suite with `cargo nextest` (plus doctests); `just test --changed` only the crates
  changed against main and their dependents (needs `tpm` on PATH). `just lint` runs clippy with `-D warnings`
  and `cargo fmt --check`.
- Tests are deterministic: no real time decides an outcome, no sleeps, seeded randomness only, concurrent things
  asserted as sets. A flaky test is a bug fixed at its cause.
- Property tests (`proptest`) for invariants: no resource over capacity, cleanup always runs, progress while
  work remains, bounded waiting with aging, Little's law on simulated traces.
- Formulas in `theory.rs` are tested against worked numbers.

## Commands

- `just` lists the recipes; `just test`, `just lint`, `just install` (build and put `choreograph` on PATH),
  `just deploy` (bring this checkout up to main and install).
- `choreograph --version` shows the version, the git SHA and the commit time.

## Commits

- Small commits with a clear subject line in the imperative; the body says why. One logical change per commit,
  with its FEATURES.md and CHANGELOG.md updates.
